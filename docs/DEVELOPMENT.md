# Разработка Corelight

Инструкция по установке и использованию находится в [README](../README.md). Архитектура, правила разработки и детали реализации описаны в [CLAUDE.md](../CLAUDE.md).

## Сборка из исходников

Для сборки нужны:

- **Windows 11 x64** — интерфейс использует WPF и системные API Windows.
- **.NET SDK 10.0** — включает инструменты сборки и среду выполнения.
- **Git**, если скачиваете исходники командой git clone. Можно также скачать ZIP репозитория и распаковать его.
- Интернет для первого восстановления NuGet-пакетов и компонентов автономной сборки.

Установите SDK через PowerShell:

~~~powershell
winget install --id Microsoft.DotNet.SDK.10 --exact --source winget
~~~

Либо скачайте **SDK для Windows x64** с [официальной страницы .NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). Способы установки описаны в [документации Microsoft](https://learn.microsoft.com/en-us/dotnet/core/install/windows).

После установки заново откройте терминал (при необходимости перезапустите VS Code). Проверьте командой **dotnet --list-sdks**, что присутствует версия **10.0.xxx**. Для клонирования проверьте **git --version**. Visual Studio для сборки командами ниже не требуется.

~~~powershell
git clone https://github.com/Shtarkerr/Corelight.git
cd Corelight
dotnet restore Corelight.slnx
dotnet build Corelight.slnx
dotnet test tests/Corelight.Tests --filter 'Category!=Integration'
dotnet publish src/Corelight.App -c Release -o publish/app
~~~

Готовая сборка с лицензиями появится в **publish/app**. Исходники движка находятся в **src/Corelight.Core**, интерфейса — в **src/Corelight.App**, тестов — в **tests/Corelight.Tests**.

Для запуска используйте **publish/app/Corelight.exe**. В эту сборку уже включён .NET. Сборке Debug нужен **.NET Desktop Runtime 10**, который входит в SDK. Для передачи тестировщикам используйте установщик или переносной пакет, описанные ниже.

## Тестирование

Полный набор запустите из терминала администратора. Интеграционные тесты помечены `Category=Integration`. Они проверяют системные API Windows и используют временные ключи реестра и файлы. Для проверок AppX, прав доступа и символических ссылок нужны повышенные права. Реальное применение, удаление приложений и откат проверяются отдельно.

~~~powershell
dotnet test Corelight.slnx -c Release
~~~

В локальной сборке после beta.6 прошли все 255 тестов Release, включая интеграционные. Перед упаковкой опубликованной beta.6 прошли 254 теста. На сборке-кандидате в виртуальной Windows 11 отдельно проверены сохранение истории при обновлении прав доступа, возврат OneDrive и возврат Microsoft To Do с предустановкой для новых профилей.

Workflow **Windows build** запускает сборку Release и обычные тесты при пуше в `main` и в pull request к `main`. После пуша в `main` или ручного запуска он также собирает Setup и Portable. Готовые EXE находятся в артефакте **Corelight-win-x64** на странице прогона. Интеграционные проверки Windows выполняются отдельно.

## Сборка установщика и переносного пакета

Для создания комплектов нужны Git, рабочая копия репозитория Corelight и [Inno Setup](https://jrsoftware.org/isdl.php) версии 6.3+ или 7. ZIP распакованных исходников подходит для обычной сборки приложения. Компилятор установщика используют только при подготовке комплектов.

~~~powershell
.\scripts\Build-Packages.ps1
# Если компилятор не найден автоматически:
.\scripts\Build-Packages.ps1 -IsccPath 'C:\путь\к\ISCC.exe'
~~~

Если политика PowerShell запрещает запуск файлов сценариев, выполните из корня репозитория без изменения политики системы:

~~~powershell
& ([scriptblock]::Create([IO.File]::ReadAllText((Join-Path (Get-Location) 'scripts\Build-Packages.ps1')))) -RepositoryRoot (Get-Location).Path -IsccPath 'C:\путь\к\ISCC.exe'
~~~

Сценарий собирает установщик **Corelight-<версия>-Setup-win-x64.exe** и переносной **Corelight-<версия>-Portable-win-x64.exe** со встроенным .NET в **publish\packages\<версия>**. В релиз GitHub прикрепляйте только эти два файла. При незакоммиченных изменениях имена пакетов получают суффикс **local**, а версия приложения в журнале — **dirty**. Скрипт ничего не коммитит и не публикует на GitHub.

Исходник установщика находится в **installer\Corelight.iss**. Перед выпуском проверьте установку, ярлыки, обновление поверх прежней версии и удаление с сохранением истории.

В локальной версии после beta.6 на финальном экране установщика можно запустить Corelight с правами установщика. Иконка Corelight встроена в приложение и видна на ярлыках и у переносного EXE.

## Диагностика и данные

- В `%ProgramData%\Corelight` находятся `backup.json` с историей, `logs\log-ГГГГММДД.txt` с журналами и `installers\OneDrive` с сохранёнными установщиками. Повреждённую историю Corelight сохраняет рядом как `.corrupt-…`.
- При первом запуске Corelight может ограничить права записи каталога со стандартными унаследованными разрешениями ProgramData. История и журналы сохраняются. При отказе проверьте владельца, права и перенаправление каталога.
- Для отката Corelight хранит снимки затронутых параметров. Незавершённые действия остаются в истории. После изменения состава настройки для отката может потребоваться версия, которой её применили.

## Подпись стабильного выпуска

Подпишите `Corelight.exe` до упаковки, чтобы Setup устанавливал подписанный файл, а Portable использовал ту же подписанную сборку. Подпишите установщик и деинсталлятор средствами Inno Setup. Проверьте доверие к подписи и наличие метки времени у финальных EXE.

На чистой Windows 11 с включённым «Интеллектуальным управлением приложениями» проверьте установку, запуск с финального экрана Setup, ярлыки, Portable и удаление программы. Используйте те файлы, которые будут распространяться.
