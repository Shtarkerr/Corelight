# Corelight

**Оптимизатор Windows 11 для игр.** Убирает фоновую нагрузку системы (телеметрию, лишние службы, предустановленные приложения, фоновые задачи), чтобы выросли минимальный FPS и стабильность кадров.

> ⚠️ **Ранняя версия.** Программа ещё не проверена на большом числе систем. Пробуйте на свой страх и риск, лучше сначала в виртуальной машине.

## Чего ожидать

Сильнее всего оптимизация сказывается на **минимальном FPS (1% low)** и плавности кадров: меньше внезапных фризов из-за фоновых задач Windows. Средний FPS на чистой системе обычно растёт в пределах нескольких процентов. Чудес вроде «+50% FPS» Corelight не обещает.

## Гарантии

- **Никакого разгона.** Частоты, напряжения, лимиты мощности, BIOS и драйверы не трогаются. Используются только штатные схемы питания Windows.
- **Безопасно для античитов** (VAC, FACEIT, Vanguard, EAC, BattlEye).
  - Secure Boot, VBS/HVCI, подпись драйверов, Defender, hosts-файл и службы античитов не затрагиваются.
  - Программа не вмешивается в игры и не работает в фоне.
- **Графика не меняется.** Ни в системе (анимации, прозрачность), ни в играх.
- **Windows Update продолжает работать.**
- **Всё обратимо.**
  - Перед первым изменением создаётся точка восстановления Windows.
  - Каждое изменение можно откатить по отдельности, программа возвращает именно те значения, что были до неё.

Ограничения проверяет код, а не только честное слово: твик, который нарушает правила, программа не загрузит (`GuardrailValidator`, покрыт тестами).

## Возможности

- **Сканирование.** Проверяет систему, ничего не меняя, и предлагает рекомендации. Безопасные пункты отмечены сразу, а пункты «Осторожно» пользователь отмечает сам. Учитывает железо: например, не отключает службу печати, если подключён принтер.
- **Расширенный режим.** Переключатели по разделам, у каждого пункта короткое описание: что это и что вы потеряете. Разделы: приложения, телеметрия, интерфейс и фон, игровые настройки, службы, сеть, автозагрузка.
- **История и откат.** Каждое изменение можно откатить по одному, или всё сразу одной кнопкой.

Нужны права администратора: от их имени меняются системные службы и политики.

## Для разработчиков

Нужен .NET SDK 10.

```powershell
dotnet build Corelight.slnx
dotnet test tests/Corelight.Tests
dotnet publish src/Corelight.App -c Release -o publish   # один Corelight.exe, .NET ставить не нужно
```

Журнал пишется в `%ProgramData%\Corelight\logs`, бэкап исходных значений — в `%ProgramData%\Corelight\backup.json`.

Тесты делятся на две группы:
- модульные, на фейковых адаптерах;
- интеграционные (`Category=Integration`), на настоящих адаптерах Windows.

Интеграционные тесты только читают систему, а запись идёт во временный ключ `HKCU\Software\Corelight.Tests`, который удаляется после теста. Запустить только модульные: `dotnet test --filter Category!=Integration`.

В Debug-сборке есть отладочный тур, который не требует прав администратора и только читает систему:
`Corelight.exe --tour=<папка>`. Он проходит по всем страницам и диалогам, сохраняет их скриншоты в указанную папку и закрывает программу.

### Структура

```
src/Corelight.Core     движок: твики, действия, бэкап, сканер, каталог
  Catalog/Data/*.json    каталог твиков (по файлу на категорию)
  Catalog/GuardrailValidator.cs
  Tweaks/TweakEngine.cs  применение и откат с бэкапом
  Actions/               registry, registryListEntry, service, task, appx, powerPlan, tcpNoDelay
  Platform/              обёртки над реестром, службами, планировщиком, AppX, powercfg
src/Corelight.App      WPF + WPF-UI, MVVM (CommunityToolkit.Mvvm)
tests/Corelight.Tests  xUnit: модульные + интеграционные
```

### Как добавить твик

Добавьте объект в нужный файл `src/Corelight.Core/Catalog/Data/*.json`:

```jsonc
{
  "id": "privacy.example",                // уникальный
  "title": "Отключить …",                  // название в виде действия
  "description": "Что это и что пользователь потеряет.",
  "warning": "Необязательно: что перестанет работать.",
  "risk": "Safe",                          // Safe | Caution | Advanced (для Advanced нужен warning)
  "impact": "Low",                         // Low | Medium | High
  "recommended": true,                     // попадёт в результаты сканирования
  "requiresReboot": false,
  "minBuild": 22000,
  "recommendWhen": [ "desktop" ],          // desktop, laptop, noPrinter, noBluetooth, ssd, hdd, hagsSupported
  "requires": [],
  "exclusiveGroup": null,                  // твики одной группы взаимоисключающие (например, схемы питания)
  "actions": [
    { "type": "registry", "path": "HKLM\\SOFTWARE\\Policies\\…", "name": "Value", "value": "0", "default": null },
    { "type": "service", "service": "Name", "startType": "Disabled", "default": "Manual" },
    { "type": "task", "path": "\\Microsoft\\Windows\\…", "optional": true }
  ]
}
```

- `default` — значение Windows по умолчанию. Нужно, чтобы откатить твик, применённый не этой программой. Для реестра `null` означает «значения нет».
- `optional: true` разрешает действию не выполниться (например, если Windows защищает задачу), не отменяя весь твик.

После правки запустите `dotnet test`: тест каталога проверит JSON и правила проекта.

### Безопасное тестирование

Применение твиков, удаление приложений и точки восстановления проверяйте **в виртуальной машине** (например, Hyper-V с контрольной точкой), а не на основном ПК:
1. Отсканировать систему и применить все рекомендации.
2. Перезагрузиться.
3. Убедиться, что работают «Пуск», поиск, Store, winget, Steam и игры.
4. Выполнить «Откатить всё».

Эффект замеряйте с помощью CapFrameX или PresentMon: одна игра, одна сцена, до и после (средний FPS, 1% low, график frametime).

## Известные ограничения

- Пути HKCU относятся к учётной записи, от имени которой запущена программа. Если обычный пользователь повышает права, вводя пароль другого администратора, настройки HKCU попадут в профиль этого администратора.
- ID приложений в Microsoft Store, по которым идёт переустановка, стоит перепроверить. У некоторых приложений (Tips, Teams, Dev Home и др.) ID нет, и вернуть их можно только вручную через Store.
- В автозагрузке пока показываются только Run-ключи и папки «Автозагрузка». Задачи планировщика, запускаемые при входе, не показываются.
- Exe не подписан, поэтому при первом запуске SmartScreen покажет предупреждение.
