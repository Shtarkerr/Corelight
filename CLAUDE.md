# Corelight — контекст разработки

Общение с пользователем, интерфейс и документация на русском. Инструкция для пользователей находится в README.md. Здесь собраны правила разработки, текущие решения и открытые задачи.

## Назначение и ограничения пользователя

Corelight — GUI для управления фоновыми функциями Windows 11. Цель — снизить лишнюю фоновую нагрузку. Прирост FPS и совместимость со всеми играми не доказаны; не обещать проценты или гарантии отсутствия блокировок.

**Аудитория — пользователи в России.** Сетевые сценарии проверять с учётом российского региона Windows/Store. Успех в другом регионе не подтверждает работоспособность в РФ. VPN не гарантирует доступность приложения.

Обязательные правила:

1. Не менять частоты, напряжения, лимиты мощности, параметры питания CPU, BIOS и драйверы. Допустимы только штатные схемы питания Windows и их копии.
2. Не трогать Secure Boot, TPM, VBS/HVCI, DSE/test-signing, bcdedit, hosts, службы античитов и файлы игр. Никаких инъекций, драйверов и резидентных бустеров. Для Defender действует отдельное уточнение ниже.
3. Не урезать графику игр и визуальные эффекты Windows: анимации, прозрачность, DWM, Control Panel\Desktop.
4. Не отключать Windows Update. Допускается отключать P2P-раздачу Delivery Optimization.
5. Проверки разработки проводить на основной Windows. Реальные изменения применять только в пределах сценария проверки и сохранять штатную историю отката.
6. Не отключать и не перенастраивать VPN пользователя: от него зависит связь с рабочей средой.
7. Microsoft Defender исключён из текущих оптимизаций. Управление им запланировано в отдельном модуле.

GuardrailValidator проверяет запрещённые цели каталога; новые действия и твики должны соблюдать эти ограничения.

- Упаковка: scripts/Build-Packages.ps1 собирает установщик Inno Setup и отдельный переносной EXE со встроенными лицензиями. В релиз GitHub прикрепляются только Corelight-<версия>-Setup-win-x64.exe и Corelight-<версия>-Portable-win-x64.exe. Контрольные суммы из SHA256SUMS.txt можно указать в описании релиза. Результаты — publish/packages/<версия>; незакоммиченные сборки помечаются local/dirty. Inno Setup 6.3+ или 7 — зависимость сборки, не приложения. Скрипт ничего не коммитит/публикует.
- Установщик installer/Corelight.iss: Windows 11 x64, Program Files, администратор, русский язык, меню «Пуск» и необязательный ярлык на рабочем столе. Общий AppId сохранять между версиями. Установка не запускает оптимизации; приложение не закрывается принудительно. Удаление оставляет ProgramData/Corelight и применённые настройки; возврат выполняется через переустановку и историю.
- Программа требует администратора. При UAC от другого администратора HKCU относится к его учётной записи. Exe пока не подписан.

~~~powershell
dotnet restore Corelight.slnx
dotnet build Corelight.slnx --no-restore -warnaserror
dotnet test tests/Corelight.Tests --filter 'Category!=Integration'
dotnet test tests/Corelight.Tests --filter 'Category=Integration'
dotnet publish src/Corelight.App -c Release -o publish/app
~~~

Интеграционные тесты читают Windows и используют свои временные ключи HKCU\Software\Corelight.Tests и тестовые файлы. Для некоторых проверок нужны права администратора. Реальное применение и откат проверяются отдельно.

В Debug есть безопасный тур интерфейса: Corelight.exe --tour=<папка>. Он читает систему, открывает страницы и диалоги, сохраняет PNG и завершает работу без применения твиков и без UAC.

Не коммитить publish, bin/obj, логи, бэкапы пользователя, ISO и файлы VM. Исходный src/Corelight.Core/Backup/ должен отслеживаться, несмотря на общее правило Backup*/ в .gitignore.

## Структура

- src/Corelight.Core/Catalog/Data/*.json — вшитый каталог шести категорий; TweakCatalog и GuardrailValidator — загрузка и проверка.
- Tweaks/ — модели действий, обнаружение, применение и откат в TweakEngine.
- Actions/ — registry, registryListEntry, service, task, appx, powerPlan, oneDrive, copilotDesktop.
- Platform/ — адаптеры реестра, служб, COM-планировщика, PackageManager, powercfg, процессов, OneDrive и настольного Copilot.
- Backup/ — JsonBackupStore; SystemInfo/ — WMI, HAGS и точки восстановления.
- Scanning/ — рекомендации с учётом оборудования; Startup/ — Run/StartupApproved и папки автозагрузки.
- Cleanup/ — анализ и необратимое удаление файлов и пустых папок. Используются правила путей, проверка идентичности открытого элемента и Shell API для корзины и ярлыков. Не проводить очистку через TweakEngine/BackupStore.
- src/Corelight.App — WPF, DI, Services, ViewModels и Views. ApplyCoordinator объединяет применение, точку восстановления, отчёт и запрос перезагрузки.
- tests/Corelight.Tests — модульные проверки на fake-адаптерах и отдельная категория Integration.

## Инварианты движка

- Capture завершается до первого изменения, исходное состояние сохраняется на диск. Повторное применение сохраняет первый бэкап для истории. При сбое повторной попытки движок возвращает состояние на момент её начала.
- Сохранение и удаление бэкапа атомарно обновляют диск до изменения кэша в памяти. Повреждённый файл сохраняется рядом как .corrupt-…; восстановление прошлой истории не обещать.
- Новые записи содержат идентификаторы целей действий. Изменение их состава блокирует переинтерпретацию старого бэкапа; старый формат без идентификаторов поддерживается по числу действий.
- Ошибка применения вызывает попытку отката всех затронутых действий, включая действие, которое изменило состояние перед исключением. Неполный или неподтверждённый возврат сохраняет бэкап.
- При тайм-ауте удаления AppX (три минуты на операцию) Corelight запрашивает отмену и останавливает очередь. Сохранять бэкап и не запускать автоматический откат, пока операция Windows может ещё завершаться. После штатного удаления перечитать состояние пакета, если оно обновляется с задержкой.
- Откат проверяет состояние после выполнения. Ошибка optional-действия допускается при применении, но не оправдывает потерю записи при откате.
- Цели, отсутствовавшие в исходном снимке, не менять при откате. RegistryListEntryAction восстанавливает свою запись, сохраняя чужие изменения в том же строковом значении; понимает старые снимки.
- Откат требует сохранённого снимка. Значение null в снимке реестра означает, что значение нужно удалить.
- exclusiveGroup допускает выбор одной схемы питания в результатах сканирования. Перед сменой схемы, применённой Corelight, пользователь откатывает её через историю.
- Ошибка чтения оборудования означает неизвестное состояние, а не отсутствие батареи, принтера или Bluetooth. Не рекомендовать отключение функций по неизвестным данным.
- Прямой запуск системных утилит использует абсолютные пути Windows. WinGet берётся из подписанного пакета App Installer текущего пользователя. Остановка отдельных служб выполняется без принудительной остановки зависимых служб.
- AppX-инвентарь обновляется перед сканированием, применением и откатом; новое сканирование обновляет сведения об оборудовании.
- Исходные данные и журнал: %ProgramData%\Corelight\backup.json и %ProgramData%\Corelight\logs.

## Интерфейс и приложения

- Главное меню расположено в заголовке окна. В «Очистке диска» категории показаны карточками слева, файлы открытой категории — справа, общая панель очистки — внизу.
- «Очистка диска» — отдельная страница с анализом, выбором категорий и отдельных файлов, подтверждением, остановкой и итоговой сводкой. Браузеры пока не очищаются.
- После каждого анализа автоматически отмечаются все карточки и найденные файлы, включая «Загрузки» и доступную непустую корзину. Пустые папки отмечаются по одной. «Выбрать все» снова отмечает карточки и файлы. Справа показаны описание и список категории по убыванию размера, сортировка доступна только по размеру. Возраст временных и диагностических файлов >7 дней, кэшей и ярлыков >1 суток. Документы, Windows Update, WinSxS и Prefetch не очищаются.
- Для «Загрузок» используется папка текущего пользователя, назначенная Windows. Возраст файлов не ограничен. Категория допускает отдельную папку на локальном диске, проверяет пересечение с защищёнными расположениями и повторно сверяет путь перед удалением.
- Очистка допускает только элементы последнего анализа (не более 30 минут, одна попытка). Повторно проверяются file ID/том, размер, времена, число жёстких ссылок, атрибуты и конечный путь дескриптора. Родительские папки удерживаются без share-delete, элемент открывается эксклюзивно и удаляется через SetFileInformationByHandle. Сохранять ACL и защитные атрибуты.
- Пустые папки любого возраста ищутся только на первом уровне стандартных локальных папок «Рабочий стол» и «Документы» текущего пользователя. Исключаются известные пути Windows и приложений, «Загрузки», расположения OneDrive, защищённые атрибуты, reparse points и каталоги с любыми записями или потоками данных. Каждая папка требует отдельной галочки. При удалении проверяются актуальная область поиска, идентичность папки и отсутствие потоков. Windows проверяет пустоту через дескриптор в момент пометки на удаление.
- Для ярлыков проверяется отсутствие цели на доступном Fixed-диске; UNC, съёмные диски, reparse-родители, MSI/виртуальные цели и ошибки доступа не означают сломанный ярлык. Перед удалением повторно проверяется цель. Список корзины читается из Windows Shell и служит для просмотра. Корзина очищается штатным SHEmptyRecycleBin для текущей учётной записи; подтверждение явно охватывает всё её содержимое, включая новое после анализа.
- Очистка не имеет отката. Не помещать её в историю обратимых настроек и не обещать восстановление точкой Windows. В диалоге показана краткая сводка удаления, на странице дополнительно указано число пропусков. Логи содержат итог, место на диске, выделенное удалённым файлам, и первые 20 причин пропуска.
- Основной список результатов сканирования сгруппирован по предполагаемому эффекту. Внутри группы порядок стабилен. Категория подписана в карточке, высокий эффект имеет фиолетовую плашку, средний — синюю, низкий показан без плашки. В «Расширенном» эффект убывает внутри категории.
- В «Рекомендуемых настройках» все галочки установлены заранее. Остальные применимые пункты можно отметить в свёрнутом разделе «Для ручной настройки». «Выбрать рекомендуемые» отмечает основной список, счётчик учитывает оба списка.
- Автоматическое обновление сохраняет галочки по идентификаторам оставшихся пунктов. Впервые появившиеся при обновлении пункты добавляются без галочки. Явный запуск сканирования восстанавливает выбор по умолчанию.
- Описания карточек и подсказки страниц — краткие, без повторов заголовка. Условия удаления, последствия и ограничения возврата оставлять видимыми; подробности — в README и «Как вернуть». Сокращение текста не должно менять действия, риск или выбор по умолчанию.
- Другие условия RegistryValueAction: requiredService проверяет наличие службы; requiredComponent — Edge по наличию exe (штатные пути/App Paths), Recall по включённому Windows Optional Feature. Проверка Recall кэшируется в пределах операции и обновляется при новом сканировании/применении/откате. Ошибка проверки не разрешает применение, сохранённый откат от условий наличия не зависит.
- Game DVR требует Xbox Game Bar; настройки WER, Delivery Optimization и MMCSS требуют соответствующих служб. Политики общих возможностей Windows не определять по наличию самого значения реестра: отсутствие значения может означать штатную работу по умолчанию.
- Инвентарь AppX запрашивает пакеты всех пользователей и provisioning; без доступа к общему списку используется текущий профиль с предупреждением в логе. У Teams наличие любого из двух вариантов пакета означает установленное приложение.
- Выбор по умолчанию сверён с заполненной таблицей пользователя. Для применения галочки нужны применимость, признак recommended и прохождение recommendWhen. Поле preselected переопределяет Safe/Caution. Пункты Advanced всегда выбираются вручную. Явный выбор галочки не меняет предупреждения и способ возврата.
- В «Расширенном» отдельные блоки «Неприменённые настройки» и «Автозагрузка». В первом показаны применимые пункты с кнопками «Применить» или «Удалить». Отмена оптимизаций доступна в «Истории и откате». После применения или отката страницы перечитывают общее состояние твиков. Изменения автозапуска отменяются тем же переключателем.
- AppX удаляется для всех пользователей и снимается с подготовки новых профилей. Для приложений со Store ID новый бэкап сохраняет семейство предустановленного пакета. После установки через Store/winget Corelight возвращает предустановку и проверяет её перед удалением записи истории. Старые бэкапы не содержат эти сведения. Остальные существующие профили, прежняя версия и данные приложения автоматически не возвращаются.
- Перед удалением выбранных AppX ApplyCoordinator проверяет установленные пакеты и доступность возврата через WinGet show. При ручном возврате или неподтверждённой доступности пользователь может пропустить эти приложения или явно подтвердить их удаление. Успешная проверка подтверждает наличие записи каталога. Сканирование системы работает без этого запроса.
- Store, App Installer/winget, Edge/WebView2, системные библиотеки, Xbox Identity Provider и GamingServices не удалять.
- История разделяет общее число записей, автоматический откат и ручной возврат. «Откатить доступное» заранее перечисляет пропускаемые пункты. Неудачные операции сохраняют запись.
- Для ручного возврата: «Открыть в Store» или официальная инструкция «Как вернуть», затем проверка исходного состояния. Открытие страницы само по себе не подтверждает установку.
- availabilityNote показывает известные ограничения до удаления и в истории. Не приписывать всем приложениям неподтверждённую региональную блокировку.
- OneDrive — отдельный Win32-адаптер. Наличие только OneDriveSetup.exe не означает установленный клиент. Проверяются обе области установки; смешанный вариант отклоняется.
- Настольный Copilot — отдельный пункт Win32. Проверяются запись удаления и клиент в Program Files, запускается подписанный деинсталлятор Microsoft. Возврат вручную подтверждается по исходному типу установки. Пакет Microsoft.Copilot обрабатывается отдельно.
- Перед удалением OneDrive проверяются важные папки, перенаправленные в облако; сначала нужно отключить их резервное копирование. Данные не удаляются, процессы принудительно не завершаются.
- Штатный установщик OneDrive проверяется по подписи Microsoft и сохраняется в %ProgramData%\Corelight\installers\OneDrive. Возврат использует ту же область установки. Интернет и повторный вход могут понадобиться; это не бэкап данных, версии клиента и настроек аккаунта.
- Точка восстановления запрашивается перед первым применением в сеансе. Corelight подтверждает появление точки в списке Windows. При неудаче пользователь видит причину и может отменить применение.

## Проверки перед выпуском

- Перед упаковкой beta.5 прошли 211 автоматических тестов. В `Corelight-Test` проверены чистая установка, обновление с beta.4, удаление и переустановка с сохранением истории, запуск интерфейса и сканирование. В гостевой Windows применены три настройки, удалён и восстановлен Microsoft To Do, проверена выборочная очистка временного файла, неработающего ярлыка и пустой папки. Откат выполнен после перезагрузки.
- Тайм-аут удаления AppX покрыт автоматическим тестом с имитацией зависания. Зависание Teams на ПК тестировщика воспроизвести не удалось.
- У OneDrive проверены оба варианта установки, сохранность локального файла и блокировка удаления при перенаправлении рабочих папок.
